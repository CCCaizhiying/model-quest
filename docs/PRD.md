# Model Quest 产品需求文档（PRD v1.0）

> 致敬《勇者斗恶龙》的 AI 大模型查询网站 —— 屠龙者，终成恶龙。
> 参考蓝本：liyupi/ai-model-world（借鉴数据源与信息架构思路，代码从零自建）

## 1. 项目概述

- **站名**：Model Quest（中文副标「模型屠龙录」）
- **一句话定位**：当前综合最强的大模型是盘踞龙座的「恶龙」，其余大模型皆为前来讨伐的「勇者」冒险者。用完整 JRPG 世界观包装的 AI 大模型查询站。
- **项目性质**：个人兴趣/作品集项目。世界观完整性与视觉冲击力优先，数据保证准确新鲜但不追求工具级全面。
- **代码路线**：从零自建，全新代码库。按未来开源标准组织代码（NOTICE、许可清单），是否开源开发完毕后再议。
- **版权策略**：原创致敬风。仅借用「像素 JRPG」这一不受版权保护的风格语言，不使用 Square Enix / DQ 的任何素材、名称、角色、配色方案；不模仿鸟山明画风。

## 2. 世界观设定（核心创意）

- **龙座与恶龙**：综合评价第一的模型 = 当代「恶龙」，盘踞魔王城，首页最高位展示，附带「在位天数」。恶龙判定采用 Epoch AI 综合能力指数（ECI）榜首；评测数据完全缺失时按透明暂定规则（最新发布）并明确标注「暂定」。
- **勇者讨伐**：其余所有模型皆为冒险者勇者，各有属性面板与门派出身，向龙座发起挑战。
- **屠龙时刻**：当新模型综合分超越现任恶龙，即「屠龙成功——少年终成恶龙」换代（v1 记录现任恶龙，换代史留作后续）。
- **厂商 = 门派/村庄**：国内外分区 = 「东土大陆 / 西洋大陆」；厂商按规模分街区（头部大街 / 主力集市 / 新兴小巷）。
- **榜单 = 武斗大会**：不同评测 = 不同赛制，分数不混算并明确标注。
- **文案腔调**：数据陈述用 JRPG 对话框腔，具体数字与事实严格忠于数据，不加戏。

## 3. 属性映射体系（数据 → RPG）

| RPG 属性 | 数据来源 | 说明 |
|---|---|---|
| 攻击（智力） | Epoch AI ECI | 核心能力条，恶龙判定依据 |
| 剑术（编程） | SWE-bench Verified | 核心能力条 |
| 体力（记性） | 上下文窗口长度 | 对数档位映射 |
| 幸运（便宜） | 每百万 token 输入价格 | 越低越幸运 |
| 职业 | 模态类型 | 文本=战士、视觉=弓手、全模态=魔剑士、图像生成=画师、视频生成=幻术师、语音=吟游诗人、嵌入=符文师 |
| 体格 | 参数量档位（命名自报） | nano/small/mid/large/colossal，未知=？？级 |
| 阵营 | 开源/闭源 | 开源义军 / 王国骑士团 |
| 出身 | 厂商 | 门派与村庄据点 |

缺失数据的属性显示空槽或「？？？」，不做臆造。

## 4. 功能需求（标准版五模块，全部已实现）

- **M-A 首页「屠龙榜」**：魔王城区（恶龙形象+属性+在位信息+挑衅台词打字机）、公会告示板、各维度榜首挑战者卡（最会编程/记性最好/最便宜/最新登场/开源最强/国产最强）、职业入口、门派速览。
- **M-B 模型图鉴**：`/bestiary/` 全量名录 + `/bestiary/[slug]/` 详情页（像素立绘、身份徽记、四维能力条、身价信息、Epoch 五项战绩表、系谱进化树、同门勇者）。恶龙页使用魔王城红框主题。
- **M-C 村庄广场**：`/village/` 双大陆分街据点图 + `/village/[vendor]/` 门派页（门面勇者、门派口号、全录）。
- **M-D 武斗大会**：`/arena/` 六大赛制（综合智力/编程/性价比/耐力/平民英雄会/新秀登场）+ 客户端阵营·大陆筛选。
- **M-E 全站检索**：`/search/` 预构建索引 + MiniSearch，认模型名/厂商名/能力词。

## 5. 数据方案（已落地）

- **合规数据源**：models.dev（MIT，元数据/价格/上下文/模态）、Epoch AI Benchmarking Hub ZIP（CC-BY 4.0，ECI/SWE-bench/GPQA/AIME/MATH）。
- **明确不用**：Artificial Analysis（禁止转存）、LMArena 站点抓取（禁止）。
- **管线**：`npm run sync` → 抓取 → 白名单过滤（剔除渠道转售）→ 日期快照去重 → 名称归一化三级模糊匹配（精确/后缀剥离/前缀+日期消歧）→ `data/models.json` + `data/sync-report.json` + `public/search-index.json`。
- **自检**：`npm run check` 纯函数自检（归一化、职业分类、匹配变体、CSV、参数解析）。
- **当前快照规模**：426 个模型 / 28 个门派 / ECI 实测匹配 123 个。models.dev 未收录的旧世代模型（如 grok3、claude-3.7）在 ECI 榜中存在但本地无图鉴条目，按缺失处理，不臆造。

## 6. 美术方案（程序化拼装，已落地）

- 16-bit 精致像素风；`src/lib/sprite.ts` 纯函数确定性生成 SVG（相同数据必出相同图）。
- 映射：体型=参数档位、配色=门派主色相、头饰武器=职业、披风华丽度=身价档、徽记=开源/闭源；恶龙专属：龙角+王冠+光轮+猩红瞳。
- DOM/CSS 内联渲染（无 canvas、无位图素材），零外部图片依赖。
- 字体：Fusion Pixel 12px proportional zh_hans（OFL-1.1，见 NOTICE）。
- 界面语言：经典 JRPG 黑底双层描边窗口、打字机对话框、分段式能力条。

## 7. 技术架构（已落地）

- Next.js 15（App Router）+ TypeScript + Tailwind CSS 4，`output: "export"` 静态导出，零后端零 API key。
- 路由：`/`、`/bestiary/[slug]`（426 页）、`/village/[vendor]`（28 页）、`/arena/[board]`（6 页）、`/search`、404。
- `src/lib/snapshot.ts` 构建期读快照；`src/lib/rank.ts` 榜单与能力条推导；`src/data/vendor-registry.ts` 唯一人工常识表（门派/主色/口号/过滤规则）。

## 9. 后续方向（Backlog）

- 屠龙编年史：记录每次恶龙换代事件
- LiveBench / Hugging Face 参数量 enrichment（当前环境网络不可达，管线预留优雅降级）
- 8-bit 音效（默认可关）、HD-2D 视觉升级
- GitHub Actions 定时 sync、部署（Vercel / Cloudflare Pages）
- 英文版 i18n

## 10. 风险与对策

- 数据源结构变动 → sync 校验失败即报错阻断；Epoch CSV 文件名/列名采用候选列表宽松匹配
- 大量模型缺评测数据 → 空槽「？？？」呈现，符合世界观
- 程序化拼装风格漂移 → 部件映射集中在 sprite.ts 单文件，可整体调优
- 版权风险 → 全原创 + 素材许可审查清单（NOTICE.md）
